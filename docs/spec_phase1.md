# Phase 1 仕様: 最小在庫取得とログ出力

## 背景
Starbucks Rewards 交換ページで、以下2商品の欠品状態が長期間続いているため、
最小構成で在庫状態を定点観測できる仕組みが必要。

- スターマグ ブラウン 296ml
- スターマグ グリーン 296ml

## 目的
- 対象ページHTMLから、指定商品の在庫状態を判定する。
- 判定結果を時刻付きで標準出力に記録する。
- まずは単発実行を対象とし、永続化・通知はPhase 2以降に分離する。

## 入出力
### 入力
- URL（デフォルト: Starbucks対象URL）
- 監視対象商品名のリスト（デフォルトは2商品）
- 実行モード（`static` / `rendered`）

### 実行モード
- `static`（既定）: HTTPで取得したHTMLをそのまま解析する。
- `rendered`: Playwrightでブラウザ描画後のDOMを解析する。

※対象ページは在庫表示をクライアントサイドJavaScriptで切り替えるため、運用時は `rendered` を推奨。

### 出力
- 1商品につき1行のログ文字列
- フォーマット:
  - `<ISO8601時刻>\t<商品名>\t<在庫状態>`

## 在庫状態と判定ルール
在庫状態は以下の4種類とする。

- `OUT_OF_STOCK`: 欠品
- `IN_STOCK`: 在庫あり/交換可能
- `UNKNOWN`: 商品は見つかったが状態判別不可
- `NOT_FOUND`: 商品名自体がHTML内で見つからない

判定手順:
1. 商品名でHTMLを検索する。
2. 見つかった周辺テキスト（前後一定文字）を判定対象にする。
3. 周辺に欠品キーワード（例: `在庫なし`, `在庫切れ`, `欠品`, `SOLD OUT`）があれば `OUT_OF_STOCK`。
4. 欠品キーワードがなく在庫キーワード（例: `在庫あり`, `交換可能`）があれば `IN_STOCK`。
5. 商品名はあるが上記キーワードがなければ `UNKNOWN`。
6. 商品名がなければ `NOT_FOUND`。

## エラー時挙動
- HTML取得失敗時は、CLIは非0で終了する。
- 例外内容は標準エラーに出力する。
- パーサは例外よりも `UNKNOWN` / `NOT_FOUND` を返し、呼び出し側で運用判断できるようにする。

## テスト観点
1. fixture HTMLで2商品の欠品判定ができる。
2. 在庫あり、不明、未出現ケースを判定できる。
3. ログ文字列が時刻・商品名・在庫状態を含む。

## 非目標（Phase 1でやらない）
- 差分検知
- 永続化
- 通知連携（Slack/メール等）
- スケジュール実行
