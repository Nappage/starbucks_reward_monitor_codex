# AIエージェント向け開発指示書

このプロジェクトは、セッションをまたいで複数AIエージェントが引き継いでも一貫した品質で進めることを目的とする。

## 1. 最優先ルール
1. **仕様先行**: 実装前に必ず `docs/` の該当仕様を更新する。
2. **TDD厳守**: Red → Green → Refactor の順序を崩さない。
3. **小さいPR**: 1PR 1目的。複数フェーズを同時に進めない。
4. **再現性**: テスト・実行手順・入力データを明示する。
5. **可観測性**: 失敗時に原因追跡できるログを残す。

## 2. 標準ワークフロー（毎タスク共通）
1. 現在のフェーズを確認（`docs/development_plan.md`）
2. 該当仕様を更新（新規なら `docs/spec_*.md` を作成）
3. 失敗テストを追加（Redを確認）
4. 最小実装でテスト通過（Green）
5. 必要最小限のリファクタ
6. 変更内容・制約・次タスクをドキュメントへ追記

## 3. ドキュメント構成ルール
- `docs/development_plan.md`: 全体計画とフェーズ管理
- `docs/spec_phaseX.md`: フェーズごとの仕様
- `docs/decision_log.md`: 設計判断（ADR簡易版）
- `docs/runbook.md`: 運用手順

### 記載テンプレート
- 背景
- 目的
- 入出力
- 判定ルール
- エラー時挙動
- テスト観点
- 非目標（今回はやらないこと）

## 4. コーディング方針（最低限）
- パースロジックとI/Oロジックを分離する（テスト容易性のため）
- 外部依存（通知、DB、HTTP）は抽象化境界を設ける
- マジック値（商品名・セレクタ）は定数管理

## 5. テスト方針
- 優先順位: 解析ロジックの単体テスト > 状態遷移テスト > E2E
- fixtureベースでDOM変化に備える
- ネットワーク依存テストは最小化し、必要時のみスモークとして扱う

## 6. 引き継ぎフォーマット（各セッション終了時に必須）
次のブロックをPR説明または引き継ぎメモに必ず含める:

```md
## Handover
- Current Phase:
- What changed:
- Tests:
- Known risks:
- Next recommended step:
```

## 7. 禁止事項
- 仕様未更新のまま実装開始
- テスト無しでのロジック追加
- 大規模変更を1PRに詰め込む
- 例外や失敗を握りつぶす実装

## 8. 次セッション開始時チェックリスト
- [ ] 現在フェーズと受け入れ基準を確認した
- [ ] 仕様変更の要否を判断した
- [ ] 失敗テストを先に書く準備ができている
- [ ] 変更を最小単位に分割した
